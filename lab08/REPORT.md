# REPORT.md

## Variant
- тема: Система планування подорожей
- номер: 6

## Model overview
У роботі реалізовано класи:

- HotelBooking — описує бронювання готелю;
- TrainTicket — описує квиток на потяг;
- MuseumPass — описує квиток до музею;
- TravelPlan — контейнер для зберігання всіх об’єктів;
- TravelPlanFileManager — клас для роботи з файлами (запис, читання, серіалізація).

## Text format
Для текстового збереження використовується формат з роздільником `;`.
Кожен об’єкт записується одним рядком, де перше поле визначає тип об’єкта.

Приклад:
HOTEL;HB001;Kyiv Central Hotel;2026-05-10;3;2400.0

Такий формат дозволяє при читанні файлу визначити тип об’єкта та правильно відновити його.

## Serialization
Реалізовано серіалізацію об’єкта TravelPlan у бінарний файл.
Для цього всі класи моделі реалізують інтерфейс Serializable.
Десеріалізація дозволяє відновити повний стан об’єкта разом із усіма вкладеними даними.

## Exception handling
Обробляються стандартні винятки вводу/виводу (IOException), а також винятки серіалізації (ClassNotFoundException).
Також створено власний виняток InvalidTravelDataException, який використовується у випадках:
- неправильна кількість полів у рядку;
- невідомий тип запису;
- помилки перетворення чисел.

## Demo scenario
У класі Main продемонстровано:
- створення об’єктів;
- додавання їх у TravelPlan;
- збереження у текстовий файл;
- читання з текстового файлу;
- серіалізацію у бінарний файл;
- десеріалізацію;
- обробку помилкової ситуації при некоректному файлі.
